## Old phones and unknown ids (said plainly)

Phones on 0.7.5 or older cannot skip an unknown exercise: that code is already on them. A test found that on those versions Today itself fails to draw from week 2 when last week holds an unknown id, and a workout in progress with one breaks the workout screens. From 0.7.6 on the app skips them. 0.7.6 adds no new exercise ids, so a 0.7.5 phone is safe with 0.7.6 data. The rule stays: update every phone that syncs before a version with new ids.

## Food search (S1): why the old address stays

On 2026-11-18 the old search address (world.openfoodfacts.org/cgi/search.pl) answered 503. The first S1 build moved the search to search.openfoodfacts.org. The round-2 auditor noted that a check from Node ignores CORS. A check with curl and headless Chrome on 127.0.0.1 then showed that search.openfoodfacts.org sends no Access-Control-Allow-Origin header, so a browser gets "Failed to fetch" and can never read it. world.openfoodfacts.org sends `*`. The master picked a: keep the old address only, plus one plain message on failure, CSP back to 0.7.5. The old address answered 200 again late on 2026-11-18; /api/v2/search was still 503.
