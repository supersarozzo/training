# Build step 11: safety review of the app

Date: 2026-11-16. Done by the task chat "training-review-11" (Opus, high effort).
Scope: all of `app/` and `tests/` (commits `33ed568..be764aa`), with a focus on [ARCHITECTURE.md](ARCHITECTURE.md) section 12.

Plain words used here:
- **Finding**: a problem the review found.
- **Severity**: how bad it is. **High** = can block your data or sync. **Medium** = a rule from the design is missing. **Low** = rare, or only with odd data.
- **Validator**: `app/js/validate.js`, the check that every backup file and every GitHub file must pass before the app uses it.

## Result in short

- 10 findings: **1 high, 1 medium, 8 low**.
- Fixed: the high, the medium and 4 lows. Not fixed: 4 lows (listed for later, with the reason).
- Every section 12 item: pass (some after a fix). See the checklist at the end.
- Tests: 246 pass with `node --test` (230 before the review, 16 new).
- No GitHub key and no body data in any file or commit (checked, see "How it was checked").

## Section 12 checklist

| Item | Result | What was checked |
|---|---|---|
| 1. Token handling | **Pass** (after F6) | The key lives only in `trn.device.v1`. Never in the data, the safety copy, the backup file or the GitHub file (tests, plus a browser check). Never in a URL: owner, repo, branch and path are checked against a strict pattern, and the key goes only in the `Authorization` header. Errors carry short codes only; no `console` calls anywhere. Password field. "Forget GitHub key" removes the key and the sync state and keeps the data. The typed draft is now dropped when Settings is left. |
| 2. Sync merge | **Pass** (after F5) | Lists join by id; later `updated_at` wins; same time: the tombstone wins, then the text order, so both phones pick the same. Property tests: nothing dropped, merging twice gives the same result, `merge(a, b)` = `merge(b, a)`, three documents in any order give the same result, an older copy never revives a tombstone, unknown fields kept. Future fields with mixed types no longer stop the merge. |
| 3. Sync flow | **Pass** (after F1) | One sync at a time, with one more round when asked during a run. An edit made during the GET or the PUT is kept (the merge result is merged again with what is stored at that moment; tested). No PUT after a failed GET, a broken file or a too-new file. 409/422 start again from the GET, 3 times at most. Every call uses `cache: "no-store"`. UTF-8 base64 both ways (emoji and "é" tested). `last_sync_at` is the start time. New: never sends a file the app could not read back. |
| 4. Data loss on the phone | **Pass** (after F1, F2) | Every set is saved the moment Done is tapped (`model.js` saves at once). A storage error now says "Not saved" instead of nothing. Migrations copy the data to `prev` first (none exist yet; see F8). A closed app resumes the workout from the device box and the saved sets. Restore checks the file, keeps a copy, then merges (an empty phone takes the file as it is). F7 is listed for later. |
| 5. Untrusted data in the page | **Pass** (after F4) | No `innerHTML`, `outerHTML`, `insertAdjacentHTML`, `document.write` or `eval` anywhere; `h()` sets text only. The CSP line in `index.html` matches ARCHITECTURE section 3 (scripts and styles only from the site, network only to the site and `api.github.com`, no inline scripts). The Shortcut link encodes the name. Every restored or synced field the screens use is checked; dangerous key names (`__proto__`) are dropped; depth and size are limited. The service worker answers only same-site GET requests, so it never sees or caches GitHub answers or the key. Note: a CSP in a meta tag can not block framing (GitHub Pages can not send headers); low risk, because a framed copy on another site has its own storage and no key. |
| 6. Body data never in the public repo | **Pass** | Tests and fixtures use made-up people. A search of every committed file for Rosario's private numbers found none. `private/` is git-ignored and was never committed. |
